# Development Guide

## Project Structure

```
chat/
├── __init__.py              # Package init, version
├── __main__.py              # CLI entry point
├── api/                     # FastAPI application
│   ├── app.py               # App factory
│   ├── dependencies.py      # Dependency injection
│   ├── schemas.py           # Pydantic models (auto-generate API docs)
│   └── routes/
│       ├── chat.py          # Chat endpoints
│       ├── models.py        # Model management
│       └── health.py        # Health + config
├── core/                    # Business logic
│   ├── config.py            # Configuration
│   ├── model_manager.py     # Model lifecycle
│   └── inference.py         # Generation engine
├── frontend/                # Web UI
│   ├── templates/
│   └── static/
├── tests/                   # Test suite
├── Dockerfile               # Container build
├── docker-compose.yml       # Deployment
└── requirements.txt         # Dependencies
```

## Setting Up Development

```bash
# Install development dependencies
pip install -e .
pip install -r chat/requirements.txt
pip install pytest pytest-asyncio httpx

# Run the development server with auto-reload
uvicorn chat.api.app:create_app --factory --reload --port 8000
```

## Running Tests

```bash
# Run all chat tests
pytest chat/tests/ -v

# Run with coverage
pytest chat/tests/ -v --cov=chat
```

## Documentation

Documentation is auto-generated from docstrings using MkDocs + mkdocstrings.

```bash
# Build documentation
cd docs
mkdocs build

# Serve documentation locally
mkdocs serve
```

The API documentation (Swagger/ReDoc) is automatically generated by FastAPI
from the Pydantic schemas and route docstrings. No manual updates needed.

## Code Conventions

- **Docstrings**: Google style, used for auto-documentation
- **Type hints**: All functions have type annotations
- **Async-first**: API handlers are async; blocking operations use executors
- **Dependency injection**: Shared state accessed via FastAPI `Depends()`

## Adding a New API Endpoint

1. Create or edit a route file in `chat/api/routes/`
2. Define Pydantic schemas in `chat/api/schemas.py`
3. Add the router to `chat/api/app.py`
4. Write tests in `chat/tests/`
5. Documentation auto-updates from docstrings

## Adding Vision-LSTM Support

The codebase is prepared for Vision-LSTM integration:

1. The `ModelVariant` enum has a reserved `VISION` value pattern
2. `ModelManager.available_variants()` lists it as "planned"
3. `ModelInfoResponse.supports_vision` flag is ready
4. The architecture doc describes how to add new variants

When Vision-LSTM becomes available, implement `_load_vision_model()`
in the `ModelManager` class and update the variant enum.
